🚲 따릉이 재배치 강화학습

서울시 공공자전거를 트럭으로 재배치하는 정책을 강화학습으로 학습
한 문장으로: 시민이 자전거를 빌리려는데 정류소가 비어있거나(stockout), 반납하려는데 가득 차서(full) 불편함을 겪는 일을 최소화하도록, N대의 트럭에게 "어느 정류소로 가서 자전거를 옮길지" 결정하는 정책을 DQN으로 학습.
데이터 (parquet) Gymnasium 환경 SB3 DQN + Action Mask 학습 결과 시각화
1

문제 정의 — 무엇을 풀려는가?

따릉이 정류소 간 자전거 불균형 → 트럭 N대로 재배치 → 24시간 동안 누적 실패 최소화.

😟 현실의 문제

오전 출근시간 → 주거지 정류소는 텅 비고, 회사 밀집 지역은 자전거가 넘쳐 가득.
→ stockout(빌릴 자전거 없음) + full(반납할 자리 없음) 발생.

🚛 우리의 해결책

트럭이 자전거를 적재(잉여 정류소) → 하차(부족 정류소).
"어느 트럭이, 언제, 어느 정류소로 가야 할까?"를 DQN이 결정.
왜 강화학습?
시간대·요일·날씨에 따라 수요 패턴이 복잡하게 변함 → 단순 규칙으론 한계. "어떤 상황에서 어떤 행동이 미래의 누적 실패를 줄이는가"를 직접 학습.

📐 결정한 설정

  • 권역: 마포구 (정류소 146개)
  • 트럭: 3대, 적재 용량 20대, 속도 25km/h
  • 시간 해상도: 1 step = 10분, 1 episode = 24시간 = 144 step
  • 제어 방식: Parameter Sharing (3대 트럭이 같은 Q-network 공유)
  • Action: 다음 갈 정류소 선택 (적재/하차 수량은 규칙 기반)

왜 parquet?
CSV 대비 10~30배 작고, 컬럼 타입 유지 + 부분 컬럼 로딩 가능. 같은 데이터를 학습마다 반복 로드하므로 빠른 I/O가 중요.
주요 변환 보기 — trip → demand 격자 
# trip 한 건 = "A 정류소에서 09:15 출발 → B 정류소에서 09:30 도착"
# 이걸 두 카운트로 분해:
#   - A 정류소의 rentals 09:10 칸 +1
#   - B 정류소의 returns 09:30 칸 +1

def trips_to_demand(trips, freq="10min"):
    starts = trips.groupby(["t_floor_start", "start_station_id"]).size()  # rentals
    ends   = trips.groupby(["t_floor_end",   "end_station_id"]).size()    # returns
    return starts.merge(ends, how="outer").fillna(0)
# 결과: (시각, 정류소) × (rentals, returns) sparse 테이블

💾 출력 파일

  • stations.parquet — 정류소 마스터 (id, lat, lon, gu)
  • demand_10min.parquet ⭐ — 학습의 핵심 입력: (시각, 정류소) × (rentals, returns)
  • trips.parquet — 개별 trip (분석용)
  • weather_10min.parquet — 날씨 (현재 활용 X)
실행 명령

python scripts/run_preprocess.py --gu 마포구 영등포구 강남구 --step 10min

환경 만들기 — 시뮬레이터 구축

DQN이 "행동을 시도하고 보상을 받는 무대". Gymnasium 표준 인터페이스.
📄 src/envs/data_loader.py 📄 src/envs/rebalance_env.py
두 단계로 나뉨
(a) data_loader가 parquet에서 episode 1개분 정적 데이터(정류소, 거리행렬, demand 격자)를 numpy 묶음(EpisodeData)으로 만들고 → (b) RebalanceEnv가 그걸 받아 시뮬레이션 시계를 굴림.

RebalanceEnv가 매 step에 하는 일

🎯 Action (Discrete)

0 ~ N-1 중 하나 = "다음 갈 정류소"
자기 위치 선택 = 머무름

👁 Observation (벡터)

정류소별 자전거 비율, 트럭별 위치/적재/잔여이동/현재차례, sin/cos(시각)
모두 [-1, 1] 범위

🎁 보상 (모두 음수 = 벌점)

항목가중치언제 발생
stockout-1.0빈 정류소에서 대여 시도 1건당
full-0.8가득 정류소에 반납 시도 1건당
이동 거리-0.01/km트럭 출발 시
이동 시간-0.005/step트럭 이동 중 매 step
1 RL step = 1 트럭의 1 결정
Parameter Sharing: 3대 트럭이 같은 Q-network를 공유. 환경이 turn을 관리하다가 idle 트럭이 생길 때마다 DQN에 "지금 누구 차례인지(current_truck_onehot)"를 알려주며 결정 요청.
step() 핵심 코드 
def step(self, action):
    truck = self.trucks[self.current_truck]
    # ① action 적용: 트럭이 그 정류소로 출발
    if action == truck.location:
        truck.remaining_steps = 1        # 머무름
    else:
        steps = self.data.travel_steps[truck.location, action]
        truck.destination = action
        truck.remaining_steps = steps
        reward += w_travel_km * km          # 거리 비용 즉시 청구

    # ② 다음 idle 트럭 생길 때까지 시계 진행
    #   - _tick() 호출: demand replay + 트럭 이동/도착
    #   - stockout/full 발생 시 페널티
    reward_advance, done = self._advance_until_next_decision()

    return self._get_obs(), reward + reward_advance, done, False, info

베이스라인 — 비교 기준선

RL과 비교할 비학습 정책. RL이 넘어야 할 합격선.
📄 src/agents/baselines.py 📄 scripts/run_baseline.py
왜 베이스라인을 먼저?
RL은 학습에 시간이 걸리고 결과 분산이 큼. "이 정도는 쉽게 가능"의 기준이 없으면 RL 결과가 좋은지 나쁜지 판단 불가. 베이스라인은 즉시 결과 측정 가능.
정책로직역할
NoopPolicy 트럭이 자기 위치에 항상 머무름 "재배치 자체가 의미 있나?" 검증용
Random 매번 무작위 정류소 최악 정책
MostImbalancedPolicy ⭐ 빈 트럭→가장 잉여 큰 곳, 가득→가장 부족 큰 곳, 부분→불균형 큰 곳 강한 휴리스틱, RL의 목표선

🎯 베이스라인 결과 (마포구 7일 평균)

  • NO-OP: -매우 안 좋음 (그냥 두면 수요 자체 패턴 따라 stockout/full 폭증)
  • most_imbalanced: -36.97 ⭐ — 이게 DQN이 넘어야 할 선
most_imbalanced 핵심 코드 
def act(self, env):
    truck = env.trucks[env.current_truck]
    bikes = env.bikes
    target = env.data.capacity * 0.5      # 목표: 절반

    # 트럭 적재 상태에 따라 점수 계산
    if truck.load == 0:
        scores = bikes - target           # 잉여 큰 곳일수록 좋음 (가서 적재)
    elif truck.load >= capacity:
        scores = target - bikes           # 부족 큰 곳일수록 좋음 (가서 하차)
    else:
        scores = np.abs(bikes - target)   # 불균형 큰 곳

    # 다른 트럭이 가는 곳은 제외 (중복 방지)
    scores[truck.location] = -np.inf
    for i, other in enumerate(env.trucks):
        if i != env.current_truck and not other.is_idle:
            scores[other.destination] = -np.inf

    return int(np.argmax(scores))

DQN 학습 — 강화학습으로 정책 학습

SB3 DQN + action mask + Double Q. ε-greedy 탐색으로 buffer 채우면서 Q-network 업데이트.
📄 src/agents/masked_dqn.py 📄 scripts/train.py

학습 루프 (DQN의 4단계 사이클)

🎭 MaskableDQN (자체 구현)

SB3 DQN에 action mask 추가. 다른 트럭이 가는 정류소의 Q값을 -inf로 처리해서 argmax가 안 고르게 함. + Double DQN 옵션.

📅 데이터 분할

train: 1~2월 중 20일 (reset마다 회전)
eval: 1/13~1/19 7일 고정
→ 매 5k step마다 자동 평가
ε-greedy 탐색
학습 초반: 무작위 행동 위주 (ε=1.0) → buffer를 다양한 transition으로 채움.
후반: ε=0.05 → 학습된 Q값 따라 최선의 action 선택 (활용).
SB3 DQN은 ε를 처음 30% step 동안 1.0→0.05로 선형 감소.
학습 실행 명령 
# vanilla DQN (마스크 없음, 기준선)
python scripts/train.py --algo dqn --tag baseline_v1

# MaskableDQN + Double Q (권장)
python scripts/train.py --algo masked_dqn --double-q --tag mapo_masked_v1

# TensorBoard로 학습 곡선 모니터링
tensorboard --logdir logs
train.py가 하는 일 (4단계) 
[1/4] episodes 로드  # load_episode × 20개 날짜 + 7개 평가 날짜
[2/4] 휴리스틱 baseline 측정  # 학습 중 비교 기준 (-36.97)
[3/4] DQN 학습  # model.learn(100k step) — 콜백이 5k마다 평가
[4/4] 모델·history 저장  # logs/<tag>/{best/, dqn_final.zip, history.npy}

원인 진단 (영향 큰 순)

  • ① action mask placeholder였음 — 학습 당시 마스크가 작동 안 해서 무의미 action에 학습 신호 낭비
  • ② Double DQN 없음 — Q value 과대추정 → 특정 정류소만 비현실적으로 좋다고 학습
  • ③ 휴리스틱이 너무 강함 — DQN이 비슷한 수준 되기 전에 발산
  • ④ travel_step=-0.005 — "안 움직이는 정책"으로 끌어당기는 힘
