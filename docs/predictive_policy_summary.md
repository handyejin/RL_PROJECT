# 예측형 휴리스틱 — 정책 정리 (2026-06-06)

> 한 줄 요약: **RL/딥러닝으로 못 넘던 휴리스틱(-500) 벽을, "미래 수요를 선반영하는 단순 규칙(예측형)"이 -460까지(상한 -383) 넘었다.** reward를 올린 레버는 학습이 아니라 **정책 설계(반응형→예측형)**였다.

---

## 1. 배경 — 기존 반응형 휴리스틱의 한계

기존 정책 `most_imbalanced`(반응형)는 **지금 이 순간** 가장 비거나 꽉 찬 정류소로 트럭을 보낸다.
→ 출근/퇴근 러시에 자전거가 **다 빠진 뒤에야** 반응 → 늦음.

진단(experiments_2026-06-03 §Step2): 휴리스틱-RL 격차의 **100%가 미충족 수요(stockout+full)**, 특히 **오전 수요 ramp 과소대응**.

**reward의 의미**: `reward = stockout×(-1.0) + full×(-0.8) + travel(미미)` ≈ **"하루 서비스 실패(못 빌림+못 반납) 건수의 음수"**. 0에 가까울수록 좋음.

---

## 2. 예측형 정책 — 30분 뒤를 보고 미리 간다

핵심 아이디어: "곧 빌/꽉 찰" 정류소를 **미리** 선점.

매 결정 시점에 각 정류소의 **H=3스텝(30분) 뒤 예상 자전거 수**를 계산:

```
예상_자전거 = 현재_자전거 + Σ_{t..t+3}(예측_반납 − 예측_대여)
```

그다음 **예상 상태**로 목표 결정 (반응형 규칙을 "현재"→"예상"으로 교체):
- 빈 트럭 → 곧 넘칠(예상 잉여 최대) 정류소 → 수거
- 가득 찬 트럭 → 곧 빌(예상 부족 최대) 정류소 → 배달
- 부분 적재 → 예상 불균형 `|예상−target|` 최대

H=3(30분)이 최적 (7일 eval 스윕: H=2 -395 / **H=3 -383** / H=6 -415 / H=18 -527).

---

## 3. forecast vs oracle — 같은 규칙, "미래 정보 출처"만 다름

| | **oracle 예측형** | **forecast 예측형 ★최종 채택** |
|---|---|---|
| 결정 규칙 | (동일) 30분 뒤 예상 불균형 큰 곳 선점 | (동일) |
| **미래 수요 출처** | 그 날 **실제** 미래 (`data.rentals[t:t+3]`) | train 292일 **같은 시간대 평균** |
| 가정 | 완벽 예지 (그날 무슨 일 날지 정확히 앎) | "이맘때 보통 이렇더라" (과거 평균) |
| 배포 가능? | ❌ 미래를 모름 | ✅ 과거 데이터만 필요 |
| 역할 | **상한선** (예측이 완벽하면 여기까지) | **실제 채택** (현실 달성 가능) |
| reward | **-382.79** (Δ+117) | **-459.65** (Δ+40) |

→ 같은 정책의 "완벽 예지 버전(상한)" vs "과거 평균 추정 버전(현실)". forecast가 oracle 이득의 **34% 회수**.
나머지 66%는 그날만의 비주기적 스파이크라 평균으론 못 잡음(수확 체감).

## 6. 최종 채택 & 사용법

- **채택 정책**: forecast 예측형 (H=3) = **-459.7 (Δ+40.4)** — 하루 ~40명 추가로 빌림/반납 성공, 즉시 배포 가능.
- 규칙 구현: `PredictiveImbalancedPolicy` (기본 H=3) — [src/agents/baselines.py](../src/agents/baselines.py)
- forecast 버전(292일 평균 프로파일): `ForecastPredictivePolicy` — [scripts/eval_forecast2.py](../scripts/eval_forecast2.py)
- 평가 재현:
  ```bash
  python scripts/eval_predictive.py     # oracle 예측형 horizon 스윕
  python scripts/eval_forecast2.py      # forecast (전체평균/요일/공휴일)
  python scripts/eval_forecast3.py      # forecast + 날씨배율
  python scripts/plot_intraday.py       # 시간대별 누적 reward
  python scripts/plot_summary.py        # 정책 비교 막대
  ```

> **clone은 채택 안 함**: 예측형을 BC로 신경망에 옮기니 -502로 이득 소실(28% 정확도로 미묘한 예측 케이스 회귀). 규칙 그대로가 최선.

## 7. 핵심 교훈

1. **이 환경에서 reward를 올린 건 RL/딥러닝이 아니라 정책 설계(반응형→예측형)였다.**
2. RL 트랙(추상화·DQfD·anneal)은 전부 휴리스틱(-500) 천장. value-RL은 좋은 prior를 개선 못 하고 깎기만 함.
3. 학습(BC/RL)은 단순 규칙을 자꾸 *밑돈다* — 예측형 clone도 실패. 규칙이 최선.
4. forecast로 oracle의 34% 회수(+40). 나머지는 per-station 비주기적 스파이크 → 정교한 수요예측 모델 필요(수확 체감).
