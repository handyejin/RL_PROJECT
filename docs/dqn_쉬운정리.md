# 강화학습(DQN)이 규칙(휴리스틱)을 이긴 실험 — 쉬운 정리

> **한 줄 요약:** 자전거 재배치 문제를 작게 줄인 뒤, "스스로 시행착오로 배우는 AI(DQN)"를 학습시켰더니, 사람이 만든 똑똑한 규칙보다 **자전거 이용 실패를 절반으로 줄였습니다.**

---

## 1. 무슨 문제를 푸는가? — 따릉이 재배치

서울 마포구의 공유자전거(따릉이) 시스템을 생각해봅시다.

- 아침 출근 시간엔 **주거지 정류소는 텅텅** 비고(다들 빌려 나감), **회사·지하철 근처는 꽉 참**(다들 반납).
- 그러면 문제가 생깁니다:
  - **대여 실패**: 빌리러 갔는데 자전거가 없음 (빈 정류소)
  - **반납 실패**: 반납하러 갔는데 거치대가 꽉 참 (가득 찬 정류소)
- 그래서 운영자가 **트럭으로 자전거를 옮겨** 균형을 맞춥니다. 이게 "재배치".

**우리 목표: 트럭을 어떻게 운전하면 "이용 실패"를 가장 적게 만들 수 있을까?**

---

## 2. 실험 환경 — 문제를 "작게" 줄였다

원래는 정류소 146개·트럭 3대·하루 종일이라 너무 복잡해서 AI가 잘 못 배웠습니다.
그래서 **AI가 배울 수 있을 만큼 작게** 줄였습니다:

| 항목 | 설정 | 쉬운 설명 |
|---|---|---|
| 정류소 | **10개** | 출퇴근에 가장 붐비는(불균형 심한) 10곳만 |
| 트럭 | **1대** | 자전거 옮기는 트럭 1대 (최대 30대 적재) |
| 시간 | **하루(출근·퇴근 피크 포함)** | 10분 단위로 진행 |
| 수요 | **확률적** | 손님이 언제 올지는 매번 조금씩 다름(예측 평균 기준 무작위) |

> 비유: 큰 도시 전체(146개) 대신, **가장 문제 많은 동네 10곳**만 떼어서 트럭 1대로 관리하는 연습 문제.

---

## 3. 점수(리워드) — "실패 횟수"가 적을수록 좋다

AI가 잘했는지 못했는지 매기는 점수는 아주 단순합니다:

```
점수 = −(이용 실패 횟수)
     = −(대여 실패 + 반납 실패)
```

- **대여 실패**: 자전거가 없어서 못 빌린 사람 수
- **반납 실패**: 거치대가 꽉 차서 못 돌려놓은 사람 수
- 실패가 적을수록 점수가 높음 → AI는 점수를 높이려고 = **실패를 줄이려고** 학습.

> 이 문서의 모든 숫자(예: 36.9, 73.6)는 **"하루 동안 일어난 이용 실패 총 횟수"**입니다. **낮을수록 좋습니다.**

---

## 4. 학습 방법 — DQN: 시행착오로 배우는 AI

**DQN(Deep Q-Network)**은 강화학습의 한 방법입니다. 쉽게 말하면:

> **아무것도 모르는 상태에서 시작해, 트럭을 수십만 번 운전해보면서 "이 상황에선 어디로 가는 게 나중에 실패를 줄이더라"를 스스로 터득하는 AI 운전기사.**

- 처음엔 **무작위로** 움직임 (백지 상태, 사람 흉내 안 냄 = "from scratch").
- 매번 결과(실패 횟수)를 보고 신경망을 조금씩 수정.
- 40만 번 운전 연습(약 4분) 후 → 똑똑한 운전 습관 완성.

AI에게 주는 정보(상태):
- 지금 각 정류소에 자전거가 몇 대 있는지
- 트럭 위치·적재량, 현재 시각
- **"수요 예보"**: 과거 데이터로 만든 "곧 어디가 빌지/찰지" 예측 ← 이게 중요(아래 6장)

AI의 행동: **다음에 어느 정류소로 갈지** 결정.

### 무슨 데이터로 학습했나?
- **마포구 따릉이 실제 데이터 60일치**를 모아 **"평균 수요 패턴"**을 만듭니다.
  (= 각 정류소가 시간대별로 평균 몇 대 빌려지고 반납되는지. 이게 곧 "수요 예보"의 재료)
- 학습할 때는 이 평균을 중심으로 **매번 무작위로 조금씩 다른 하루**를 만들어 줍니다(동전 던지듯).
  → AI가 "운 좋은 날·나쁜 날"을 골고루 수십만 번 겪으며 튼튼하게 배움.
- **평가에 쓰는 실제 7일은 학습에 절대 안 씁니다**(따로 빼둠) → "처음 보는 날에도 잘하나"를 확인.

> 한 줄: **60일 평균 패턴 + 무작위성으로 연습 → 본 적 없는 실제 7일(+가상 30회)로 시험.** (사람 시험으로 치면, 기출 60일로 공부하고 새 문제 7일로 평가.)

### 그림으로 보는 학습·평가 과정

**① 학습 과정 (DQN이 스스로 연습하는 단계)**

```
  [마포구 따릉이 실제 60일]
          │  정류소·시간대별 평균 계산
          ▼
  [평균 수요 패턴 λ] ───────────────────►(수요 예보로 DQN에 입력)
          │
          │  매 연습마다(에피소드)
          ▼
  [Poisson 무작위 수요]  =  "조금씩 다른 하루" 생성
          │
          ▼
 ┌──────────────── 환경(시뮬레이터) ────────────────┐
 │  10정류소 · 트럭1대 · 하루(10분 단위)             │
 │                                                  │
 │   ① 상태 ───────────────────────►  ┌──────────┐  │
 │   (재고·트럭위치·시각·수요예보)     │   DQN    │  │
 │                                    │  신경망  │  │
 │   ② 행동(어느 정류소로) ◄───────────└──────────┘  │
 │          │                              ▲        │
 │          ▼                              │        │
 │   ③ 결과: 실패수 → 리워드 ──────────────┘        │
 │                        (Q값 업데이트 = 학습)      │
 └──────────────────────────────────────────────────┘
          │
          │  ①→②→③ 루프를 40만 번 반복 (≈4분)
          ▼
     [학습 완료된 DQN]   ← 똑똑한 운전 습관 완성
```

**② 평가 과정 (학습 끝난 뒤 실력 측정 — 학습 안 함)**

```
   [학습 완료 DQN]      [규칙들: do-nothing / STR / SLA]
         │                          │
         └────────────┬─────────────┘
                      ▼   똑같은 환경 · 똑같은 리워드 잣대로 측정
        ┌──────────────────────────────────────┐
        │  평가 A: 가상 수요 30회 (Poisson 무작위) │
        │  평가 B: 실제 7일 (학습에 안 쓴 데이터)  │
        └──────────────────────────────────────┘
                      │
                      ▼   각 정책의 평균 리워드 (높을수록↑ 좋음)
              do-nothing  −139
              STR(반응형)   −74
              SLA(예측형)   −67
              DQN          −32   ◄── 가장 높음 = 추월 ✅
```

> **핵심 차이**: 학습 단계는 DQN이 **무작위 하루들로 시행착오하며 신경망을 고치는** 과정이고(①②③ 반복), 평가 단계는 **다 배운 DQN을 고정한 채** 규칙들과 같은 조건에서 점수만 매기는 과정입니다(학습 X).

## 5. 비교 상대 — 사람이 만든 규칙 3가지(휴리스틱)

"휴리스틱"은 학습 없이 **정해진 규칙**대로 움직이는 방법입니다. 셋과 비교했습니다:

| 이름 | 규칙 (쉬운 설명) | 똑똑함 |
|---|---|---|
| **do-nothing** | 아무것도 안 함 (트럭 안 움직임) | ★ |
| **STR (반응형)** | "지금 이미 문제 생긴 정류소"로 달려가 고침 | ★★ |
| **SLA (예측형)** | **"곧 문제 생길 정류소"를 예보로 미리 찾아가 고침** | ★★★ |

- **SLA(예측형)**이 가장 똑똑한 규칙입니다. 미래 수요를 보고 미리 대응하니까요. **이게 우리가 넘어야 할 진짜 상대.**

---

## 6. 결과 — DQN이 가장 똑똑한 규칙을 절반으로 이겼다

하루 동안 이용 실패 횟수(낮을수록 좋음):

| 방법 | 실패 횟수 | 한 줄 평 |
|---|---|---|
| do-nothing (방치) | **159** | 재배치 안 하면 이만큼 실패 |
| STR (반응형 규칙) | 82 | 문제 터지면 달려가 고침 |
| SLA (예측형 규칙) | 74 | 미리 예측해 대응 — 규칙 중 최강 |
| **DQN (학습한 AI)** | **37** ⭐ | **최강 규칙의 절반!** |

> **DQN이 가장 똑똑한 규칙(74)의 절반(37)으로 실패를 줄였습니다.** 방치(159)와 비교하면 1/4 수준.

## 7. "진짜 이긴 게 맞아?" — 검증 (어블레이션)

운 좋게 나온 결과가 아닌지, 무엇 덕분에 이겼는지 하나씩 떼어보며 확인했습니다:

| 확인한 것 | 결과 | 의미 |
|---|---|---|
| 다른 난수로 재실험 | 37 (동일) | ✅ **운빨 아님, 재현됨** |
| 보조장치(shaping) 제거 | 30 (여전히 이김) | 보조장치 덕 아님 |
| 행동 단순화(규칙과 똑같이) | 36 (여전히 이김) | 행동 자유 덕 아님 |
| **수요 예보 제거** | **70 (거의 비김)** | **예보가 큰 승리의 핵심** |

**결론적으로 큰 승리의 두 기둥:**
1. **수요 예보를 AI에게 줌** — 미래 정보 (승리폭의 대부분)
2. **AI의 똑똑한 경로 학습** — 규칙은 매번 "가장 급한 한 곳"만 가는 근시안인데, AI는 **하루 전체를 내다본 더 나은 순회 경로**를 배움

> 비유: 예측형 규칙은 "지금 제일 급한 불부터 끄는 소방관", AI는 "어디서 불이 날지 예보를 보고 동선을 최적화해 미리 도는 소방관".

## 8. 왜 예전(146개)엔 못 이겼는데 지금은 이겼나?

- 예전 **146개 정류소·하루**: 경우의 수가 너무 많아 AI가 좋은 전략을 **못 배웠음**(규칙을 못 넘음).
- 지금 **10개로 축소**: AI가 충분히 배울 수 있는 크기 → 규칙의 빈틈(근시안)을 파고들어 **추월**.

> **핵심 교훈: 강화학습은 "배울 수 있을 만큼 작은 문제"에서, "미래 정보(예보)"를 주면, 사람이 만든 똑똑한 규칙도 이길 수 있다.**

---

## 8.5 정류소를 늘리면? — 추월의 "한계선"

그럼 정류소를 10개에서 점점 늘리면 어떻게 될까요? (트럭은 1대 고정, 같은 학습량)

| 정류소 수 | DQN이 예측형보다 | 누가 이김? |
|---|---|---|
| 10개 | +35 점 좋음 | **DQN 승** ✅ |
| 15개 | +53 점 좋음 (격차 최대) | **DQN 압승** ✅ |
| 20개 | +24 점 좋음 | **DQN 승** ✅ |
| 30개 | −32 점 (뒤짐) | 예측형 승 ❌ |
| 50개 | −56 점 (더 뒤짐) | 예측형 승 ❌ |

```
 DQN이 더 좋음 ↑
   +50 │   ●(15)
   +25 │ ●(10)  ●(20)
     0 ┼──────────────●─── ← 여기서 역전 (20~30 사이)
   −25 │              ●(30)
   −50 │                  ●(50)
       └──10─15─20─30─50──  정류소 수
 예측형이 더 좋음 ↓
```

**무슨 뜻?**
- 같은 연습량(40만 번)에선 **정류소 20개까지는 DQN이 이기고, 25~30개부터 예측형 규칙이 이깁니다.**
- 재미있는 건 **15개일 때 AI 우위가 가장 큼** — 너무 작으면(10개) 문제가 쉬워서 규칙도 잘하니 차이가 작고, 적당히 복잡할 때(15개) AI의 똑똑함이 가장 빛납니다.

### 그런데 — 이 한계선은 "벽"이 아니라 "연습량" 문제였다 ✅
30개에서 진 게 "AI 능력의 벽"인지 "연습 부족"인지 확인하려고 **연습량을 2배(80만 번)로** 늘려 다시 학습시켰더니:

| 정류소 30개 | DQN | 예측형 | 결과 |
|---|---|---|---|
| 연습 40만 번 | −271 | −239 | DQN 패 ❌ |
| **연습 80만 번** | **−234** | −239 | **DQN 승 ✅ 회복!** |

→ **30개에서 진 건 "능력의 벽"이 아니라 "연습 부족"이었습니다.** 연습을 더 시키니 다시 이겼어요.

**진짜 결론:**
- AI가 이길 수 있는 크기에 **고정된 벽은 없습니다.** 다만 **문제가 커질수록 필요한 연습량이 가파르게 늘어납니다.**
- 그래서 아주 큰 문제(예전 146개)는 *원리상 못 이기는 게 아니라*, **현실적으로 감당 못 할 만큼 많은 연습이 필요**해서 어려웠던 겁니다.

> 비유: AI는 더 넓은 구역도 맡을 수 있지만, 구역이 넓어질수록 **훈련 기간이 기하급수로 길어진다.** 트럭을 2~3대로 늘리면 한 대가 맡는 부담이 줄어 더 큰 구역도 쉽게 이길 것으로 예상.
