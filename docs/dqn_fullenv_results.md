# DQN(전체 환경) 실행 결과 및 한계

> 자치구 전체 정류소를 대상으로 한 일반 DQN 실험 기록. 두 자치구 모두에서
> 예측형 휴리스틱을 넘지 못해, 환경을 축소한 `dqn_small`로 전환한 근거를 정리한다.

## 1. 실험 설정

기존 팀 DQN 소스(MaskableDQN)를 우리 수정 데이터(공공 수요예측 + 실제 거치대 수)에
적용하고, 자치구 **전체 정류소**를 대상으로 학습했다. 행동 폭증을 막기 위해
candidate Top-K(forecast_imbalance, K=12, zone static3)로 **행동 후보만 12개로 제한**했으나,
**상태(state)는 자치구 전체 정류소를 그대로 사용**한다.

| 항목 | 영등포구 | 마포구 |
|---|---|---|
| 상태 차원(obs_dim) | 1,131 | 851 |
| 행동 수(candidate Top-K) | 12 | 12 |
| 학습량(timesteps) | 200,000 | 200,000 |
| 평가 | 고정 7일 holdout | 고정 7일 holdout |
| 비교 기준 | most_imbalanced 휴리스틱 | most_imbalanced 휴리스틱 |

실행 커맨드(요지):

```
python -m src.agents.run_interactive --algorithm dqn --district {구} \
  --processed-dir data/processed_seoul_all \
  --forecast-path data/forecast_by_gu/demand_forecast_1h_{구}.parquet \
  --candidate-top-k 12 --candidate-mode forecast_imbalance \
  --candidate-travel-coef 0.20 --candidate-zone-mode static3 \
  --candidate-zone-penalty 1.0 --candidate-feature-mode basic --device cpu
```

## 3. 학습 곡선 — "학습이 안 된다"

| timesteps | 영등포 eval | 마포 eval |
|---:|---:|---:|
| 20,000 | −1865.4 | −528.4 |
| 40,000 | −1875.0 | −533.4 |
| 60,000 | −1891.2 | −551.4 |
| 80,000 | −1908.6 | −547.3 |
| 100,000 | −1912.5 | −520.3 |
| 120,000 | −1937.9 | −555.7 |
| 140,000 | −1948.7 | −537.9 |
| 160,000 | −1905.4 | −552.5 |
| 180,000 | −1892.8 | −513.4 |
| 200,000 | −1933.6 | −518.2 |
| **best** | **−1865.4 (20k)** | **−513.4 (180k)** |
| **휴리스틱** | **−1811.6** | **−500.0** |

핵심은 **어느 체크포인트에서도 휴리스틱 수준에 도달하지 못했다**는 점이다. 영등포구는
학습이 진행될수록 오히려 보상이 **악화**(−1865→−1948)되다 후반에 소폭 회복했고,
마포구는 전 구간 **휴리스틱 아래에서 정체·진동**했다. best 값이 학습 초반(영등포 20k)에
나온다는 것은 학습으로 정책이 개선되지 않았음을 뜻한다.

## 4. 해석 — 문제 크기가 학습을 막는다

행동은 Top-K로 12개까지 줄였지만, **상태 공간은 자치구 전체 정류소(영등포 obs_dim 1,131 /
마포 851)로 여전히 거대**하다. 이 규모에서는 상태·신용할당(credit assignment) 폭발로
model-free DQN이 "탐욕 휴리스틱보다 나은 비탐욕 정책"을 학습하지 못한다. 예측형
휴리스틱(most_imbalanced)은 매 step 가장 불균형한 곳을 그리디하게 처리하는 **강한
베이스라인**이며, 주어진 학습량(200k step)으로는 DQN이 이를 넘지 못했다.

## 5. 결론 → DQN-small로 전환

전체 환경 DQN은 두 자치구 모두에서 휴리스틱을 추월하지 못했고 **학습 진전 자체가
관찰되지 않았다.** 이는 알고리즘 결함이 아니라 **문제 크기 대비 학습 난이도**의
문제다. 따라서 환경을 "배울 수 있는 크기"로 축소하는 방향으로 전환했다:

- **출퇴근 불균형 압력 top-N 정류소(기본 15개)만 선택** → 상태·행동 공간 대폭 축소
- **트럭 1대** → 신용할당 단순화

구현: `src/agents/ours/common/dqn_small_core.py` (기존 소스 무수정, 신규 추가).
실행: `python -m src.agents.run_interactive --algorithm dqn_small ...`
