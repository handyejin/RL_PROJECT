## Step 0 — 기존 seed best-of-seed 평가 ❌ 효과 없음

가설: 이미 학습된 `bc_v6_s43`, `s44`가 -506.6보다 나은 seed일 수 있다. 추가 학습 없이 best 비교.

방법: training-time eval이 곧 deterministic 7일 fair 평가(shaping/urgent_bonus OFF)이므로 각 run stdout의 "베스트"가 그대로 det. 평균.

| 모델 | 휴리스틱 | best | best step | Δ |
|---|---:|---:|---:|---:|
| bc_v6 main | -500.02 | **-506.57** | 5,000 | -6.55 |
| bc_v6 s43 | -500.76 | **-506.57** | 5,000 | -5.81 |
| bc_v6 s44 | -499.36 | **-506.57** | 5,000 | -6.21 |

### 결과: 세 seed가 완전히 동일한 best (-506.57)에 수렴

- best가 step 5,000(BC prior 직후, RL 거의 시작 전)에 나오고 deterministic 평가라 **seed와 무관하게 동일한 값**.
- seed는 step 5,000 *이후* RL 탐색에만 영향 → 거기서는 전부 -715 수준으로 똑같이 발산.
- **결론: best-of-seed / 앙상블로는 -506.57을 못 넘는다.**

### 함의 (진단 확정)

- 현재 성능 = **BC prior + 거의 0의 RL**. seed/RL은 레버가 아니다.
- 다음 레버는 (a) BC prior 자체 개선, 또는 (b) **forgetting을 막아 RL이 step 5k 너머로 개선하게 하는 것** → Step 1(LR 낮춤), Step 3(BC anchor)로 직결.

### 부수 발견: 휴리스틱 측정 noise

- 고정 7일인데도 휴리스틱 baseline이 run마다 **-499.4 ~ -500.8 (±1점)** 변동.
- 절대 격차를 0.x점 단위로 비교할 때 감안 필요. (env reset/heuristic RNG의 잔여 randomness 추정.)

## Step 1 — fine-tune LR 1/10 ❌ best 개선 실패 (단, 진단 확정)

가설: best가 5k에서 멈추고 이후 forgetting으로 추락 → LR을 `1e-4 → 1e-5`로 1/10 낮추면 가중치를 살살 바꿔 BC prior를 덜 망가뜨리고 5k 너머로 개선될 것.

명령:
```
python scripts/train.py --tag bc_v6_lr1e-5_100k \
  --pretrain logs/bc_v6b/bc_model.zip --timesteps 100000 --lr 1e-5
```
(lr_decay ON → `1e-5 → 1e-6`. 그 외 bc_v6와 동일)

### 학습 곡선 비교

| step | bc_v6 (lr 1e-4) | **Step1 (lr 1e-5)** |
|---:|---:|---:|
| 5k~10k | **-506.57** (best) | **-506.57** (best) |
| 30k | -635.5 | -523.9 |
| 50k | -718.6 | -532.5 |
| 100k (마지막) | -715.97 | -557.20 |

### 결과
- **best는 여전히 -506.57** (휴 -500.02, Δ -6.56). best step만 5k → 10k로 약간 이동.
- LR 낮춤이 **forgetting은 확실히 완화** — 마지막 reward -715 → -557로 추락 폭 크게 감소, 곡선이 부드러워짐.
- 그러나 **best를 BC prior(-506.57) 위로 올리지는 못함.**

### 핵심 함의 — RL은 어떤 LR에서도 BC prior를 못 넘는다

- Step 0(seed 무관 동일 best)에 이어 Step 1(LR 무관 동일 best)도 **-506.57이 천장**임을 확정.
- 즉 **RL fine-tune 단계가 긍정적 기여를 전혀 못 하고 있다.** -506.57은 100% BC prior의 성능이고, RL은 그것을 (느리게든 빠르게든) 깎기만 함.
- 레버는 RL 하이퍼파라미터(seed/LR/forgetting 완화)가 **아니다**. 남은 방향은 둘 중 하나:
  1. **BC prior 자체를 더 좋게** (단 BC acc는 misleading — 데이터/표현이 본질)
  2. **왜 RL이 못 넘는지 정책 수준 진단** → 휴리스틱이 이 masked 환경에서 거의 최적인지, reward landscape가 평탄한지 확인 (Step 2)

> 결론: Step 3(BC-anchored 정규화)도 "RL이 BC 위로 개선 가능"을 전제하는데, Step 0·1이 그 전제를 약화시킴. **Step 2 진단을 먼저** 하는 게 합리적.

## Step 2 — 05-17 진단 ✅ 원인 특정: 오전 demand ramp 과소대응

방법: fair eval 환경(shaping OFF, config 동일)에서 휴리스틱·bc_v6 best를 각각 굴려
reward를 구성요소(stockout / full / travel)로 분해하고 시간대별 누적 격차 추적.
스크립트: [scripts/diag_0517.py](../scripts/diag_0517.py)

episode: 146 정류소, 144 step, rentals 3,599 / returns 3,586 (저수요 날)

### 최종 비교

| 지표 | 휴리스틱 | RL(bc_v6) | 차이(RL-휴) |
|---|---:|---:|---:|
| 총 reward | -280.3 | -341.6 | **-61.3** |
| 재고소진(stockout, 건) | 194 | **229** | **+35** |
| 만차(full, 건) | 99 | **133** | **+34** |
| 이동거리(km) | 798.3 | 688.4 | **-109.9** |

### reward 구성요소 분해

| 요소 | 휴리스틱 | RL | 기여 격차 |
|---|---:|---:|---:|
| stockout (×-1.0) | -194.0 | -229.0 | **-35.0** |
| full (×-0.8) | -79.2 | -106.4 | **-27.2** |
| travel (km+step) | -7.1 | -6.2 | +0.9 |
| **합계** | **-280.3** | **-341.6** | **-61.3** |

### 핵심 발견

1. **격차의 100%가 미충족 수요** — stockout -35 + full -27 = -62. travel은 오히려 RL이 +0.9 (덜 움직임).
2. **RL은 휴리스틱보다 110km *덜* 움직인다** (688 vs 798). 즉 격차 원인은 "과잉 이동 비용"이 아니라 **과소 대응** — 트럭을 덜 굴려서 빈/만차 정류소를 더 많이 방치.
3. **격차는 오전 demand ramp에서 전부 발생** — 시간대별 누적 Δreward:
   - t=30 (step24): 0 (동일)
   - t=55 (step72): **-8.4** (벌어지기 시작)
   - t=82 (step144): **-70.4** (격차 거의 완성)
   - t=144 (끝): -61.3 (이후 평탄, 오후엔 추가 격차 거의 없음)
   → **오전 7~13시(t≈55~82) 수요 급증 구간에서 RL이 못 따라가고, 그 손해가 종일 유지됨.**

### 해석

- 05-17은 *가장 쉬운(저수요)* 날인데 RL이 가장 크게 진다 = 저수요 날에는 휴리스틱의 "가장 불균형한 곳으로 즉시 이동"이 거의 최적이고 싸다. RL의 학습된 정책은 **오전 ramp에서 너무 소극적**(이동·재배치량 부족).
- BC prior가 휴리스틱을 모방했지만 **모방 정확도 20%** → 오전 피크의 결정적 순간(어디로 갈지)을 제대로 못 따라함. Step 0·1에서 본 "RL이 BC를 못 넘는다"와 일관 — BC가 휴리스틱을 부분만 복제했고, RL은 그걸 개선 못 함.

### 함의 — 다음 레버 후보

- **(가장 유력) BC 데이터를 오전 피크 가중 샘플링** — 오전 ramp 결정을 더 많이 학습시켜 prior 자체를 강화. Step 0·1이 "BC prior가 천장"임을 보였으므로 prior 개선이 정공법.
- travel penalty가 RL을 과도하게 소극적으로 만들 가능성 — `w_travel`을 더 작게(또는 0) 두고 BC 재학습/fine-tune 테스트.
- 저수요 날엔 휴리스틱이 사실상 oracle → "어려운 날에서만 RL 우위" 전략으로 평균을 맞추는 방향도 가능.

## Step 3 — travel penalty 제거 (#1 가설) ❌ 기각

가설: RL이 휴리스틱보다 110km 덜 움직인다(Step 2) → travel penalty 때문에 Q-learning이
"이동 = 손해"로 잘못 배워 소극적. penalty를 0으로 없애면 RL이 더 적극적으로 움직여 개선될 것.

명령:
```
python scripts/train.py --tag bc_v6_notravel_100k \
  --pretrain logs/bc_v6b/bc_model.zip --timesteps 100000 \
  --w-travel-km 0 --w-travel-step 0
```
(train·eval·휴리스틱 모두 travel-free → 공정 비교)

### 학습 곡선 (휴리스틱 -492.57, travel 제거로 +7.5)

| step | reward | Δ(휴) |
|---:|---:|---:|
| 10k (= BC prior, RL 시작 전) | **-499.83** (best) | -7.26 |
| 30k | -629.7 | -137 |
| 50k | -709.4 | -217 |
| 100k | -705.5 | -213 |

### 결과: 가설 기각

- **best -499.83 (Δ -7.26)** — bc_v6의 Δ -6.55와 사실상 동일(노이즈 범위, 오히려 약간 나쁨).
- **post-20k 곡선이 이전과 거의 똑같이 -705로 추락** — travel penalty를 없애도 RL의 발산 패턴이 전혀 안 바뀜.
- 즉 **travel penalty는 RL 소극성의 원인이 아니다.**

### 함의 — 진짜 원인은 BC prior의 모방 충실도

- RL이 "덜 움직인다"는 건 RL이 학습한 게 아니라 **best = BC prior 자체의 행동**(learning_starts=20000 전 시점). BC가 휴리스틱을 20%만 복제 → 오전 피크 결정을 부분만 따라함 → 그래서 덜 움직이고 stockout/full 방치.
- travel penalty(Q-learning 신호)도, seed도, LR도 전부 best를 못 바꿈 → **유일하게 남은 레버는 BC prior의 모방 품질, 특히 오전 demand ramp 결정.**

## Step 4 — BC v7 오전 피크 가중 🏆🔥 **평균 첫 추월**

가설(Step 2 직결): 격차가 오전 demand ramp(env t≈44~90)에서 전부 발생 → BC가 그 구간 결정을
더 정확히 모방하면 prior가 강화될 것.

구현 ([scripts/pretrain_bc.py](../scripts/pretrain_bc.py)):
- 데이터 수집 시 각 (obs, action) 쌍의 결정 시점 `env.t` 기록
- `--peak-start/--peak-end/--peak-weight` 추가 → `WeightedRandomSampler`로 피크 구간 oversample

```

  --lr 3e-3 --batch-size 128 --peak-start 44 --peak-end 90 --peak-weight 3.0
```

## Step 5 — peak-weight 스윕 (2 / 3 / 5) → **3.0이 최적 확인**

데이터 재수집 생략 위해 `pretrain_bc.py`에 `--dataset` 옵션 추가(수집된 npz 재사용).

| peak-weight | BC best acc | RL best (7일 평균) | Δ(휴 -500.02) |

| **3.0** | 0.233 | **-494.23** | **+5.79** ✅ 🏆 |

### 결과
- **weight 3.0이 sweet spot.** 2.0은 가중 부족(+2.9), 5.0은 **과가중 → 추월 실패(-2.8)**.
- 과가중(5.0)이 해로운 이유: 피크 구간(38.7%)을 너무 키우면 나머지 시간대(저수요·야간) 결정 학습이 희석됨.
- **BC acc는 또 무의미** — 최고 평균(w3.0)이 셋 중 acc 최저(0.233). w2.0이 acc 0.268로 최고지만 결과는 나쁨.

### 함의
- 단순 weight 노브로는 w3.0(+5.8)이 천장. 추가 개선은 **가중 구조 자체**(윈도 위치/다중 피크) 또는 **퇴보한 날 표적 진단** 필요.
